# 新手开发流程审查

日期：2026-11-08。对象为组合源码仓库的文档、构建、模板生成、打包与绒绒族验证流程。

## 结论

适合愿意编辑 XML、能安装开发工具的新手，从原版外观模板开始学习。第一阶段不用写 C#；毛茸茸外观与专有行为放到第二阶段。当前还不是无依赖的一键工具：需要自己的游戏、Harmony、核心 UI 素材及编译器；公开仓库没有附带绒绒图集。传统 Unity 运行时仍需单独实机验证。

## 已修正的问题

| 问题 | 影响 | 修正 |
| --- | --- | --- |
| 相对输出路径按进程目录解析 | PowerShell 执行 Set-Location 后，模板、核心 DLL 或源码 ZIP 可能写到错误位置 | 使用 PowerShell 当前路径解析输出参数 |
| 绒绒构建只编译 AtlasRendering.cs | 新手新增的 C# 类被静默遗漏，XML 找不到类型 | 编译 Source 下所有 C#，新增可选 CoreAssembly 引用参数 |
| 两个构建脚本发现规则不一致 | 核心可自动找到的 Managed 目录，绒绒构建默认找不到；编译器还需手动填写 | 绒绒支持 Managed 发现和 SDK 编译器发现，缺 SDK 时给出明确提示 |
| 子项目文档依赖组合仓库上层路径 | 单独核心源码包与试玩包中出现失效链接 | 子项目本地链接改为包内可用入口，组合教程保留在顶层 |
| 试玩包没有准备素材脚本，验证器只识别源码布局 | 按包内说明操作会缺脚本，或找不到模组路径 | 包含准备脚本；准备与验证兼容两种布局，只复制运行内容，避免把测试目录复制进自己 |
| 验证输出目录过深 | 旧 csc.exe 会把确实存在的 DLL 报成找不到 | 增加路径长度提示及 RunRoot 参数，可指定短输出路径 |
| 运行素材不齐也能开始本地打包 | 产出不完整的试玩包 | 打包前检查必需 DLL、图集与证据截图 |
| 迎新时间与餐费说明不准确 | 玩家误以为固定两天来一次、整批只扣一份餐 | 明确随机有效等待、阻塞暂停、按人数扣餐，以及可能同时来两位成人 |
| ZIP 使用与工具安装步骤省略 | 解压后检查工具缺 Git 初始化，编译器路径无从填写 | 补充工具入口、SDK 与 Runtime 区别、ZIP 初始化及两种编译路线 |
| 第一次练习缺少可见目标 | 新手不知道改哪里、成功时应该看到什么 | 增加修改迎新灯 label、预期目录、编译成功提示、第一次游戏验收步骤 |

## 验证结果

13 项开发流程检查通过：切换目录后的模板路径；中文与 XML 特殊字符；已有目录保护；核心相对输出；新增子目录 C# 的编译失败检测；核心适配器引用和相对输出；新类型实际存在于 DLL；Managed 目录布局发现；核心与组合 ZIP 相对输出；两类源码 ZIP 本地文档链接；新 ZIP 初始化 Git 后的仓库检查。

Managed 发现检查用当前游戏程序集构造目录布局，没有使用传统 Unity 游戏运行，因此不构成传统 Unity 兼容验证。当前机器没有 .NET SDK，实际编译使用独立 Roslyn；SDK 自动选择分支未在真实 SDK 安装环境完成编译验收。

从独立试玩包布局执行绒绒族探针，使用短输出目录：

```text

PASS checks=29 errors=0
```

加载日志错误扫描通过。此轮未修改游戏 C# 或 XML 行为，主要验证改后的开发与交付脚本。未重新覆盖所有种族组合、旧档升级、全部衣物和多人联机；不能把这次审查解释为全项目没有任何 bug。
